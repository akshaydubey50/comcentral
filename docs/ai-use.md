# AI collaboration and review

This record explains how AI contributed, where its proposals were corrected, and how to inspect the result. Entries are retrospective summaries unless an exact prompt was actually retained; they are not reconstructed transcripts. Current execution results belong only in [validation.md](validation.md), and work status in [tasks/todo.md](../tasks/todo.md).

## Working method

The user defines scope and product decisions. The coordinator breaks work into bounded slices, agrees shared contracts, assigns separate file ownership, reviews changes and integrates evidence. Independent agents implement or review non-overlapping work; there is no nested delegation. Generated code or documentation is a proposal until checked against source and meaningful execution.

For implementation/review slices recorded here, supported workers used `gpt-5.6-sol` with high reasoning. Earlier full-reference reviews ran in batches; the documentation cleanup used two workers plus the coordinator. Parallelism accelerated independent work but did not replace integration checks. No measured productivity percentage or claim of complete AI correctness is inferred.

## What was learned from PayScope

The [reference documentation tree](https://github.com/meganathan-tech24/PayScope/tree/f6da3bb170eee144fddf312529e83533bfe6fba5/docs) was reviewed on 2026-10-15 alongside its README and CLAUDE.md. It used four main Markdown documents: requirements, architecture, design notes and AI prompts. ComCentral adopts focused entry points and traceable tradeoffs, while separating API/domain rules and operational evidence where its workflows need precision. Fewer files alone do not prove production readiness; large journals and mutable pending instructions are not copied into agent rules.

ComCentral retains its approved Next.js/MUI/Prisma/Better Auth stack, revocable sessions, decimal-string boundaries, salary audit/version protection, atomic CSV preview/commit, pending pay and persisted dated FX. Reference features such as additional roles, static conversion rates or a different backend layout are not automatically requirements. No reference source code or design assets were copied. The original feature/security comparison and corrections are preserved in the [dated documentation history](archive/2026-10-15-documentation-history.md#source-docs-payscope-comparison-md).

## Evidence limits

Source inspection, intercepted UI responses, real isolated PostgreSQL persistence, built-browser checks and hosted HTTPS checks establish different facts. A feature path, generated test, old pass count or polished demo does not prove the current revision is release-ready. Test/setup failures remain failures until a bounded correction and rerun establish the result. No timeout increase, skipped assertion, fabricated data, invented rate or unobserved deployment is used to close acceptance.

For the complete original request summaries, review findings, rejected alternatives and earlier execution sequence, use the [frozen AI record](archive/2026-10-15-documentation-history.md#source-docs-ai-use-md). Future entries should add one bounded task/date row and link actual evidence rather than repeating the entire work log.
